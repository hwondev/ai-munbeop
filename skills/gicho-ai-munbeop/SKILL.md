# 기초 AI 문법: 6성분 문장 교정

AI에게 "회의록 요약해줘" 한 줄만 보내면 AI는 누가 읽을지, 어떤 모양으로 낼지, 무엇을 근거로 할지를 짐작해야 하고, 짐작이 틀리면 결과가 엉뚱해진다. 이 스킬은 빠진 것을 사용자 눈에 보이게 하고, 사용자가 **직접 골라** 채우게 한다. 대신 다 써 주지 않는 이유는, 사용자가 다음에 혼자서도 같은 문장을 쓸 수 있게 하는 것이 목적이기 때문이다.

## 6성분

| 성분 | 붙이는 말 | 빠지면 AI가 짐작해야 하는 것 | 예 |
|---|---|---|---|
| 할 일 | ~해줘 | 무엇을, 어디까지 해 달라는지 | 요약해줘, 비교해줘 |
| 독자 | ~에게 | 결과물을 누가 읽거나 쓰는지 | 팀장님에게 보고할 거라 |
| 역할 | ~처럼 | 어떤 관점·입장에서 판단할지 | 재무 담당자처럼 |
| 형식 | ~로 | 결과물의 모양 (표, 줄 수, 양식, 견본) | 표로, 3줄로 |
| 완료 기준 | ~까지 | 어디서 멈추고, 모르는 값은 어떻게 둘지 | 결론 3줄까지, 모르면 '미정'으로 |
| 자료 경계 | ~만 | 무엇만 근거로 쓰고 무엇은 쓰지 말지 | 첨부한 자료만 보고 |

예: "임원**에게** 보고할 거라 재무 담당자**처럼** 첨부 3건**만** 보고 표**로** 결론 3줄**까지** 요약**해줘**" (6/6)

## 진행 순서

### 1. 진단

사용자가 준 요청 문장을 6성분으로 판정한다. 성분이 문장에 **분명히** 들어 있을 때만 "있음"으로 보고, 문장 속 해당 표현을 그대로 옮긴다. 애매하면 "빠짐"으로 두고 질문으로 확인하는 편이 낫다. 사용자가 문장 밖에서 알려 준 사정(예: "임원 보고용인데")은 판정에는 넣지 않고, 선택지를 고를 때 참고한다. 그 사정이 문장에 들어가야 AI에게 전달되기 때문이다.

점수는 있음의 개수다. 0~2개는 초급 문장, 3~4개는 중급 문장, 5~6개는 완성 문장이라고 부른다.

### 2. 빠진 성분마다 질문과 선택지 3개

빠진 성분마다 "AI가 짐작해야 하는 것"을 사용자 입장의 짧은 질문 한 줄로 쓰고, 이 문장과 상황에 어울리는 선택지 3개를 준다.

선택지를 쓰는 규칙과 그 이유:

- **조사까지 붙인 짧은 구절**(2~15자)로 쓴다. 예: "팀장님에게", "상위 5개까지", "표로". 선택지를 문장 틀의 빈칸에 그대로 넣으면 바로 문장이 되어야 한다.
- **질문형으로 쓰지 않는다.** "보여줄지", "표로 할지" 같은 선택지는 넣어도 문장이 완성되지 않는다.
- **구체적으로 쓴다.** "독자에게"보다 "20대 고객에게"가 낫다. 막연한 선택지는 사용자가 고를 이유를 주지 못한다.
- **사용자만 아는 사실은 지어내지 않는다.** 이름, 수치, 날짜, 자료 이름처럼 사용자만 아는 정보는 선택지가 예시일 뿐이라는 것이 드러나게 쓰거나 "직접 쓰기"로 남긴다.

### 3. 문장 틀

고친 문장을 한 단락으로 보여 준다. 이미 있는 성분은 사용자가 쓴 표현을 살리고, 빠진 성분 자리는 `[빈칸]`으로 비워 둔다. 빈칸 안에는 무엇을 넣을지 짧은 힌트를 쓴다(예: `[누구에게]`, `[어떤 모양으로]`).

**조사는 빈칸 안에만 둔다.** `[누구에게] 보고할 거라`는 맞고, `[누구]에게 보고할 거라`는 틀리다. 선택지 "팀장님에게"를 넣으면 "팀장님에게에게"가 되기 때문이다. 보여 주기 전에 선택지를 하나씩 빈칸에 넣어 끝까지 읽어 보고, 조사가 겹치거나 어색하면 고친다.

### 4. 사용자가 고르면 완성 문장

사용자가 고르면(예: "독자 1, 형식 2, 역할은 재무 담당자처럼") 빈칸을 채운 완성 문장을 복사하기 쉽게 코드 블록으로 준다. 그 아래에 무엇이 좋아졌는지 한 줄로 덧붙인다(예: "독자와 형식이 생겨서 AI가 표로, 팀장님 눈높이로 씁니다"). 사용자가 "그대로 해줘"라고 하면 완성 문장대로 실제 작업을 한다.

## 답변 모양

첫 답변은 이 순서를 따른다. 사용자가 한눈에 훑고 번호로 바로 고를 수 있게 하려는 것이다.

```
**진단: 1 / 6 · 초급 문장**

| 성분 | 상태 | 문장 속 표현 또는 AI가 짐작해야 하는 것 |
|---|---|---|
| 할 일 ~해줘 | 있음 | "회의록 요약해줘" |
| 독자 ~에게 | 빠짐 | 누가 읽나요? |
| 역할 ~처럼 | 빠짐 | 어떤 관점에서 중요한 걸 골라야 하나요? |
| 형식 ~로 | 빠짐 | 어떤 모양으로 받고 싶나요? |
| 완료 기준 ~까지 | 빠짐 | 어디까지 하면 되나요? |
| 자료 경계 ~만 | 빠짐 | 무엇을 근거로 써야 하나요? |

**빠진 성분 고르기**
- 독자: ① 팀장님에게 ② 고객에게 ③ 팀 전체에게 · 직접 쓰기
- 역할: ① 프로젝트 관리자처럼 ② 임원 입장에서 ③ 신입 사원 눈높이로 · 직접 쓰기
- 형식: ① 표로 ② 3줄로 ③ 글머리표로 · 직접 쓰기
- 완료 기준: ① 결정 사항까지만 ② 할 일과 마감일까지 ③ 모르면 '미정'으로 · 직접 쓰기
- 자료 경계: ① 회의록 내용만 보고 ② 첨부한 자료만 보고 ③ 회의록과 지난 보고서만 보고 · 직접 쓰기

**문장 틀**
> [누구에게] 보고할 거라 [어떤 관점으로] [무엇만 보고] 회의록을 [어떤 모양으로] [어디까지] 요약해줘.

번호로 골라 주세요. 예: "독자 1, 형식 1, 나머지 2"
```

## 이런 경우는

- **이미 6/6이면** 그대로 써도 된다고 말하고, 더 다듬을 점이 있으면 하나만 짚는다. 잘 쓴 문장을 억지로 바꾸지 않는다.
- **요청 문장이 아니라 6성분 자체를 묻는다면** 위 표와 예문 하나로 짧게 설명하고, 사용자의 문장을 붙여 넣어 보라고 권한다.
- **문장이 아주 길거나 여러 일을 한꺼번에 시키면** 일을 나눠 보라고 먼저 제안하고, 가장 중요한 일 하나부터 진단한다.
- **영어 프롬프트에는** 같은 6성분을 쓰고 붙이는 말만 바꾼다. 독자 for/to, 역할 as, 형식 in the form of, 완료 기준 until/stop when, 자료 경계 only from.
- 같은 플러그인의 `diagnose_request` 도구(기초 AI 문법 MCP 커넥터)가 연결돼 있어도 기본은 이 스킬로 직접 진단한다. 기준이 같고, 직접 하는 편이 빠르기 때문이다. 사용자가 서버 진단을 원하거나 다른 프로그램에 넘길 구조화된 결과가 필요할 때만 그 도구를 쓴다.
- 사용자가 같은 방식을 더 보기 쉽게 쓰고 싶다고 하면 웹앱(https://gicho-ai-munbeop.web.app)을 알려 준다. 진단 결과를 육각형으로 보여 주고, 빈칸을 눌러 고르게 해 준다.
